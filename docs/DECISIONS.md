# Decisions

## 2026-11-01
- The LLM writes a validated recipe of relations, never coordinates or code (competitors that let the LLM write coordinates suffer overlaps and objects in water).
- Terrain and placement run in the browser (real-time streaming); AI and model work run in Python.
- Endless chunked noise terrain plus a 1024 m authored core.

## 2026-11-02
- Task 25 (director): imports the shared `wait` from `ui/wait.ts` instead of redefining it (ruling M7). Beyond the plan, the director is single-flight, stops cleanly on Esc (sliced pauses), awaits `generate()` and stops if it returns false, and in `finally` cancels any open preview and clears `app.cinematic`. A failed or ignored edit step only toasts; the next step still runs.
- Task 24 fix round 1 (asset re-requests): world rebuilds call `ModelSource.load` for every object, so `AssetModelSource` now remembers misses. `resolveAsset`/`assetJob` mark transport failures (network, timeout, 429, 5xx, unreadable body) as `{status:'none', transient:true}`; an HTTP-200 none or another 4xx is definitive. Definitive misses are not asked again for 10 min (the limiter window; this also covers limiter refusals), and transient misses or failed GLB loads for 45 s. Any transport failure opens a source-wide breaker for 30 s with no asset requests at all, so an offline edit costs nothing. After the window a single probe decides whether to resume. `reset()` clears misses and the breaker; it is called on `generate()` and when `health()` answers ok. A failed boot health check changes nothing, because of Render cold starts. In-flight dedupe and the success cache are kept. This supersedes the earlier "every resolve fails fast" note.
- Task 24 fix round 1 (pads on keep): `Placement.padded` records whether the solver laid a pad (`padAllowed` passed), and kept placements re-pad only when it is true. Before, every kept non-prop was padded, which flattened up to about 10 m of terrain under warned "at" spots on undo or the next edit. Pads are also laid in solve order (`orderPlaces`) whether kept or new, with every kept placement counted for spacing from the start. Pads blend in sequence, so a rebuild that keeps every placement gives the identical pad list and heights. A fresh solve is unchanged. Regression tests: `tests/world/keepPads.test.ts`.
- Task 24 fix round 1 (spawn wait): `generate()` waits for the spawn chunk through `waitUntil` (ui/wait.ts) for at most 20 s of frame time (a hidden tab does not count), and fails fast when `ChunkManager.failed()` reports that the spawn chunk used up its retries (`ChunkQueue.gaveUp`). On failure it clears the overlay, shows "The terrain could not be loaded — reload or try another world" and returns false; the start screen stays up.
